# Installation (Windows on-premise)

Status: the installer **build** and an **installed-layout smoke test** are verified in CI. Running the wizard on a clean Windows machine, upgrade, backup/restore and uninstall are **not yet tested** (RELEASE_CHECKLIST).

## Build the installer (developer)

Requirements: Windows x64, .NET 10 SDK, Node.js 22.

```powershell
./installer/scripts/build-release.ps1
```

The script: builds the frontend with `VITE_API_URL=/api` (`npm ci --legacy-peer-deps`), publishes `PCS.API` self-contained win-x64 to `backend/publish/PCS.API`, publishes `PCS.Launcher`, then publishes `PCS.Installer`, which bundles all three into `backend/src/PCS.Installer/Setup/PCSSetup.exe` and prints its SHA-256. CI (`.github/workflows/installer-build.yml`) runs the same script and uploads `PCSSetup.exe` as an artifact (7 days).

## Installed layout

Default root `%LOCALAPPDATA%\PCS`; the installer runs `asInvoker` (no UAC) and installs no Windows service.

```
PCS/
  Backend/    PCS.API.exe + appsettings.json
  Frontend/   built SPA served by the API
  Launcher/   PCS.Launcher.exe
  Database/   PCS.db
  Config/     pcs.config.json
  Backup/
  Logs/
```

The launcher starts `PCS.API.exe --urls http://localhost:5000`. The API serves the SPA and `/api` from that one origin, so no CORS entry is needed.

## Configuration (`Backend\appsettings.json`)

| Key | Purpose |
|---|---|
| `Hosting:Mode` | `OnPremise` (installer) or `Cloud` |
| `Database:Provider`, `ConnectionStrings:DefaultConnection` | `Sqlite` with an absolute path, or `SqlServer` |
| `Jwt:Secret/Issuer/Audience/ExpirationMinutes` | generated per install (random 64-byte secret) |
| `InitialAdmin:*` | one-time bootstrap account; the password is blanked after first seeding |
| `Cors:AllowedOrigins` | explicit origins, needed only when the SPA is hosted elsewhere |
| `Swagger:Enabled` | default off; never on in Cloud mode |

On first install the administrator password is generated by the installer. Record it when the wizard shows it; it is not stored after the first start.

## Behavior by mode

- **New install:** creates directories, creates the database and applies migrations, writes configuration, deploys API, frontend and launcher, shortcuts.
- **Repair/upgrade:** refuses to regenerate secrets or bootstrap credentials; requires the existing `appsettings.json`.
- **Uninstall:** retains database, backups and user exchange files by default; removing user data is an explicit option.

## Known limits

Single workstation only (API binds to `localhost`); SQL Server needs a trusted TLS certificate; the relative default DB path applies outside the installed layout. See KNOWN_ISSUES F-12 to F-14.

## Recovery

Before any upgrade, copy `Database\PCS.db` and `Backend\appsettings.json` to `Backup\`. Restore by stopping `PCS.API.exe`, replacing the same files, and starting again. This procedure is not yet exercised by an automated test.
